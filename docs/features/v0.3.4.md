# v0.3.4: CI/CD pipelines, containers and leaked secrets (2026-11-03)

## Why

We compared secdev with nine similar repos on GitHub, including gedik, fortify, devsecops-skills, appsec-skills and claude-security-skills. Two gaps showed up in the checklist itself:

- nothing reviewed the CI/CD pipeline;
- the hook detected `docker`, but no control reviewed containers.

A third, smaller gap was what to do, in order, when a secret leaks.

Sources, checked on 2026-11-03:

- the official repository `OWASP/www-project-top-10-ci-cd-security-risks`, for the CICD-SEC IDs and titles;
- `OWASP/CheatSheetSeries`, `Docker_Security_Cheat_Sheet.md`, for the container rules.

## Checklist (`skills/security-checklist/SKILL.md`)

| Control | What it checks | Standard |
|---|---|---|
| **P1-10 (new)** Hardened CI/CD pipeline | `pull_request` rather than `pull_request_target` with a checkout of the PR code; minimum `permissions:` (`contents: read`); third-party actions pinned to a full commit SHA and updated by Dependabot or Renovate; `persist-credentials: false`; deploy secrets in protected environments; no self-hosted runners on public repos | CICD-SEC-3 Dependency Chain Abuse, CICD-SEC-4 Poisoned Pipeline Execution (PPE), CICD-SEC-5 Insufficient PBAC (Pipeline-Based Access Controls), CICD-SEC-6 Insufficient Credential Hygiene |
| **P2-08 (new)** Containers | Non-root `USER`; base image pinned by digest or exact version; no secrets in `ENV`, `ARG` or `COPY`; `.dockerignore` excludes `.env` and `.git`; no Docker socket mounted, no `privileged: true`; capabilities dropped, `no-new-privileges`, read-only filesystem where possible; image scanned in CI | OWASP Docker Security Cheat Sheet, rules 1-4, 8, 9, 12 and 13 (outside ASVS) |
| P1-08 Incident response | Leaked secret, in this order: revoke or rotate it, check the provider's access logs, then purge history (`git filter-repo`) and force-push. Purging without rotating protects nothing | Outside ASVS |

This repo's own `.github/workflows/test.yml` already meets P1-10: the action is pinned to a SHA, `contents: read`, `persist-credentials: false`, and Dependabot has a 7-day cooldown.

The skill `description` now also mentions CI/CD workflows and Dockerfiles. A new eval case, `ci-deploy-workflow`, covers it.

## Hook (`PostToolUse`)

Two new path categories:

- `CI/CD pipeline (P1-10, P0-04)`: `.github/workflows/*.yml`, `.gitlab-ci.yml`, `azure-pipelines.yml`, `bitbucket-pipelines.yml`, `cloudbuild.yaml`;
- `containers (P2-08, P0-04)`: `Dockerfile`, `Dockerfile.*`, `*.Dockerfile`, `compose.yaml`, `docker-compose*.yml`, `.dockerignore`.

## Tests

`hooks/risk.test.mjs` covers both categories, including Windows paths, and checks that a text file that only mentions Dockerfiles does not warn. The structure test still checks that every category points to controls that exist.
