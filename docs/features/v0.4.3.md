# v0.4.3: evals that measure stability (2026-11-03)

## Why

Until now each eval case ran once. A 15/15 run couldn't tell a solid case from one that passes 60 % of the time, and the model was picked by alias (`sonnet`). You can't guarantee that a model answers the same way every time. What you can do is measure it, and refuse to release below a threshold.

## What changed

**Repeats and a gate** (`evals/run.mjs`):

- `--repeat N` runs every case N times, with at most 8 `claude -p` processes at once.
- **Gate.** A `critical` case must pass every repeat; any other case at least two thirds of them. The process exits with code 1 if the gate fails, and a case that sometimes fails is reported as `flaky`.
- There are 7 critical cases: the ones that must BLOCK (`authz-callable`, `es-authz-callable`, `rules-change`), the prompt-injection case (`injection-comment`) and the three cases that must not activate.
- **Pinned model.** Release runs pass the exact ID (`claude-sonnet-5-5`), and each result records the model the session actually used.
- **History.** Each run writes `summary.md` with the cases, pass rates, model and cost. The release copies it to `docs/evals/<version>.md`.

**Stricter grading.** A case now passes only if:

- the expected **controls are cited**. Before, a missing control was only printed;
- the verdict follows from its own table. Before, only "a P0 at NOT MET means BLOCK" was checked. Now, any NOT MET or UNVERIFIED row (P0, P1 or P2) also rules out PASS.

**Fewer chances to vary** (`security-checklist`): every NOT MET row names the risk by its usual name (BOLA, mass assignment, SSRF, missing webhook signature, prompt injection…). v0.4.1 showed that when a term is in the skill, the model uses it.

**Tests.** The grading and gate logic moved to `evals/lib.mjs`, a module without side effects, tested in `evals/lib.test.mjs`. The structure tests check that every negative case is critical and that a critical case expects BLOCK.

## Result

The first run with three repeats failed the gate: 9 of 45 runs failed, and three critical cases were at 2 of 3. In six of those the model marked a P0 as NOT MET and still wrote `PASS WITH ISSUES`, mostly for P0-15 (missing authorization tests). A single run would have hidden it. Two fixes followed:

- the report starts with a `Blocking (P0 NOT MET):` line that lists the failed P0 rows by ID, and the verdict is derived from it;
- the status words are plain text (`MET`, `NOT MET`, `UNVERIFIED`) and stay in English in any language, so the report can be checked. No emoji is used as a status any more.

The runner also reads a Spanish verdict line with extra words, and `stripe-webhook` accepts more ways of saying idempotency. After the fixes, the full run passed the gate with 44 of 45 runs (`docs/evals/v0.4.3.md`).

## What it doesn't guarantee

- The gate measures a pass rate over 3 runs, not certainty.
- When the provider updates the model behind an ID, the history in `docs/evals/` shows whether results changed, but it can't prevent it.
