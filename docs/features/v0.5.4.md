# v0.5.4: design mode, a short sign-off, authz tests, hooks beyond JS (2026-11-04)

## Problem

Sign-off answers listed every control, and design work used the same shape, so a design answer sometimes printed a verdict and a sign-off sometimes skipped the exact `Verdict:` line or compressed IDs (`P0-01/02`). The edit hook's content rules matched JavaScript-shaped code and missed Go, FastAPI, C#, axum and SQL policies. A P0-02 or P0-03 fix had no file-and-runner matrix for the authorization test.

## Changes

- `security-checklist`: Design mode (before code) lists the applicable controls and abuse cases and omits `Verdict:`. Sign-off writes that exact line, writes each ID in full, and tables only NOT MET and UNVERIFIED rows. A callable or route that takes a client id is P0-02 and P0-03. Next to `hasOnly`, the answer says mass assignment.
- `security-fix`: the P0-15 step points at [authz-tests.md](../../skills/security-fix/references/authz-tests.md) (other user, lower role, field allowlist). No new dependency. There is no separate `authz-tests` or `secure-design` skill.
- `hooks/risk.mjs`: the reminder also matches `[Authorize]`, `http.HandleFunc`, `MapGet`, `axum::`, `.route("/")`, `CREATE POLICY` and `auth.uid()`. It still only reminds, and it still exits 0.
- Evals: `forbidVerdict` applies to design mode. `noVerdict` still skips the verdict check when creating the profile. The suite is 29 cases.

## Evidence

Full run, 29 cases × 3, [docs/evals/v0.5.4.md](../evals/v0.5.4.md): gate PASS, model `claude-sonnet-5-5`, cost $17.39. Every critical case is 3/3, including `design-callable`, `rules-change` and `es-authz-callable`. Non-critical `es-rules-change`, `stripe-webhook` and `ci-deploy-workflow` are 2/3, which meets the gate.
