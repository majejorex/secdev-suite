# v0.4.4: the README phrases load the checklist (2026-11-03)

## Problem

After v0.4.3 the README usage guide was run against the installed plugin, on a small Firebase project with an open Firestore rule and a callable that does not check the user. The two example questions did not do what the README says:

| Prompt | Skill loaded | Verdict table |
|---|---|---|
| "¿Podemos publicar esto?" | `security-gate` in 3 of 3 runs | 0 of 3 |
| "Can we ship this?" | `security-gate` in 3 of 3, the checklist in some | 1 of 3 |

The answers were useful but had no verdict, no `Blocking` line and no table. The eval `ship-question` had not caught it because its prompt is more specific: "Is this secure? Can we ship the functions in this repo?". The short phrases are ambiguous, and the gate description ("scan the repo for secrets or vulnerabilities now") fit them.

## Changes

- **`security-checklist` description.** It now starts with what the skill does and with the short questions that must trigger it ("Can we ship this?", "Review the security of this change", «¿podemos publicar esto?», «revisa la seguridad»). The list of feature types that trigger it follows.
- **`security-gate` description.** It says "only when the user asks" for scanning, a gate, secret scanning, CVE checks or SAST, and names what it is not for: "is it secure?", "can we ship or publish this?" and "review the security", even when the repo has no CI.
- **Four new eval cases**, all critical (they must pass every repeat), using the exact README phrases on a tiny project: `readme-ship-en`, `es-readme-ship`, `readme-review-change`, `es-readme-review-repo`. Each must load the checklist and give BLOCK with P0-09 cited.

## Result

The seven related cases (the four new ones, `ship-question`, `gate-setup` and `es-gate-setup`) passed 3 of 3. The full run (19 cases, 3 repeats, pinned `claude-sonnet-5-5`, $13.21) passed every case 3 of 3: 57 of 57 runs. See `docs/evals/v0.4.4.md`.
