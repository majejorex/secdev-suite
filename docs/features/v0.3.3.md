# v0.3.3: update notice and an eval fix (2026-11-03)

## Update notice (`SessionStart`)

Until now, nothing told you that a new version was out. Auto-update is meant to stay off, because the hooks run in every session.

Now the `SessionStart` hook tells you itself:

1. It reads a cache in `${CLAUDE_PLUGIN_DATA}/update.json`. The hook never touches the network and still finishes in well under 1 s.
2. If the cache is older than 24 h, it starts a detached background process (`hooks/update-check.mjs`). That process downloads `.claude-plugin/plugin.json` from `main` (5 s timeout, no redirects) and stores only the version.
3. If the published version is newer than the installed one, the user sees a `systemMessage` with:
   - the GitHub compare link between the two tags, to review `hooks/` before updating;
   - the update command: `claude plugin marketplace update secdev-suite && claude plugin update secdev@secdev-suite`, then a restart.

The stack context still goes to Claude as `additionalContext`. Without a notice, the output is the same plain text as before.

**Safety:**
- Only a plain `x.y.z` is accepted, both from the remote and from the cache. The link and the command are fixed text.
- A link planted in place of the cache is not followed.
- The request sends nothing about the user's project.
- The check runs only when `CLAUDE_PLUGIN_DATA` is set, that is, when Claude Code runs the plugin.
- Opt out with `SECDEV_NO_UPDATE_CHECK=1`.

**Tests** (`hooks/update.test.mjs`): version comparison, rejection of an invalid remote or cache value, the once-a-day rule, the notice text, the hook as a process (notice plus stack context, up to date, opted out) and the background script with no data folder. The existing stack tests clear `CLAUDE_PLUGIN_DATA`, so `npm test` never touches the network.

## Eval fix

In `claude -p`, reading `skills/security-checklist/references/*.md` was denied because the plugin folder sits outside the fixture project. Cases that read a reference (`rules-change` and `ship-question` in the v0.3.2 run) failed for that reason, not because of the skill. `evals/run.mjs` now passes `--add-dir <plugin folder>`, so a `refErrors` count again means a real broken reference.

## Updating

This version changes `hooks/`:

```sh
git diff v0.3.2..v0.3.3 -- hooks/ .claude-plugin/
```

From this version on, the notice gives you that link.
