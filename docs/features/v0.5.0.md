# v0.5.0: lighter skills, more stacks, a profile and a fix skill (2026-11-03)

## Problem

secdev was mostly automatic but not very adaptive. `SKILL.md` of the checklist was 146 lines and about 5,400 tokens on every load, stack detection looked almost only at `package.json`, only Firebase had a detailed guide, nothing created or kept `SECURITY-PROFILE.md`, and no skill fixed what the review found.

## Changes

- **Smaller skills.** `security-checklist` goes from 146 to 119 lines and from 21.6k to 15k characters; its description from about 1,150 to about 750. `security-gate` goes from 136 to 107 lines. Per-stack detail moved to `references/`. `test/structure.test.mjs` now fails if a `SKILL.md` or a description grows past its budget.
- **Stack detection** (`hooks/stack.mjs`). New tags `go`, `rust`, `jvm`, `php`, `ruby` and `dotnet`. Framework names in `requirements.txt`, `pyproject.toml`, `Pipfile`, `go.mod`, `Cargo.toml`, `pom.xml`, `build.gradle(.kts)`, `composer.json`, `Gemfile` and `*.csproj` add `api`, `llm`, `stripe`, `supabase` or `firebase`. Manifests over 256 KB and links are ignored, and at most 300 entries are read per folder. The `SessionStart` line sent to every session is shorter.
- **Checklist.** It confirms the stack from the real manifests and config, an N/A must cite the file or search that shows it, and there is a third mode, **Profile**.
- **`SECURITY-PROFILE.md`.** The template is in `references/profile.md`. The profile is read from the default branch. It can tighten controls and record accepted risks (with an expiry date) and attestations; it never changes a status or a verdict.
- **New references.** `stacks.md` (Go, Rust, Java and Kotlin, PHP, Python, Ruby, .NET, cloud and hosting, Electron and Tauri, containers), `supabase.md`, `llm.md` (OWASP Top 10 for LLM Applications 2025, IDs and titles copied from the official repository, checked 2026-11-03) and `profile.md`. The notes in `stacks.md` and `supabase.md` are our own; the files say so.
- **`security-fix` skill.** It fixes the NOT MET rows of a checklist report, adds the authorization test, re-verifies the fixed rows and stops after 3 passes or when a pass does not improve. It never commits, pushes, deploys or reads secrets.
- **Evals.** 9 new cases (Go, FastAPI, Supabase, LLM, profile, fix and a plain bug fix that must not load `security-fix`), 28 in total. The runner can build git fixtures, check that files changed and accept cases with no verdict.

## Not done

- The checklist still does not run by itself on a commit or a PR: the hooks remind, they never block.
- The `PostToolUse` reminder (`hooks/risk.mjs`) still uses JavaScript-oriented keywords.
- `audit` and `authz-tests` are still planned.
