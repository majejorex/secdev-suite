# v0.3.2: coverage gaps from CCN-STIC-812 and general AppSec guidance (2026-11-03)

## Why

We compared the checklist with three outside sources:

- a general list of application security practices;
- the CCN-STIC-812 guide (*Seguridad en entornos y aplicaciones web*, June 2023), annex "Lista de comprobación y requisitos";
- the OPSWAT post "13 application security best practices" (April 2023).

About 80 % of what they ask for was already covered. This version closes the gaps that can be checked in code or config. Requirement IDs were checked on 2026-11-03 against the official `OWASP/ASVS` repository, folder `5.0/en`.

The skill `description` now also mentions desktop windows or IPC, app signing and over-the-air updates. A new eval case, `desktop-electron-ipc`, covers it.

### Adjustments made while checking the sources

- **HTTP → HTTPS redirect.** The general advice is "redirect all traffic". ASVS 4.1.2 says only user-facing endpoints should redirect, so a client that sends a token to an API over HTTP fails visibly instead of being redirected silently. The checklist follows ASVS.
- **EAS Update code signing** is only available on Expo's paid plans (Production or Enterprise). An unsigned OTA channel is therefore ⚠️ (risk accepted in writing), not ❌.
- **Antivirus and metadata stripping** sit inside a P0 row but are marked ⚠️ when missing. Otherwise every upload feature would block, and ASVS ranks them L2 (5.4.3) and L3 (14.2.8).

### Deliberately not added

| Suggestion | Why not |
|---|---|
| Obfuscation and anti-tampering as a requirement | Already covered as optional (MASVS-RESILIENCE). They only matter for banking, DRM or anti-fraud threat models |
| Mandatory WAF/IDS, egress filtering | Infrastructure that the code doesn't show. P0-08 and P0-13 cover what the code can show |
| Training and awareness, third-party contract clauses | Organizational, not checkable in a repo |
| Formal risk analysis per ENS category | The skill's Design mode and P2-06 cover threat modeling at the right size |
| LDAP injection, SAML | Not in the target stacks; P0-05 and V10 already cover the general case |
| Vendor file-scanning products (CDR, ICAP, multiscanning) | Marketing; the vendor-neutral part (antivirus scan) is in P0-14 |

## Hooks

Both hooks still exit 0, run in under 1 s and print at most 2 lines.

### `SessionStart` (`hooks/stack.mjs`)

- New `desktop` tag: `electron` or `@tauri-apps/api` in `package.json`, or `src-tauri/tauri.conf.json`.
- `@capacitor/core` now counts as `mobile`.
- The reminder line also names app signing and updates.

### `PostToolUse` (`hooks/risk.mjs`)

- **More descriptive.** Each category now names the controls to look at first, for example: `[secdev] This change touches: auth and sessions (P0-01, P0-06), file uploads (P0-14). …`. The IDs come from a fixed map (`CONTROLS`), never from the repo.
- **New categories:**
  - `desktop windows and IPC`: `BrowserWindow`, `webPreferences`, `ipcMain`, `contextBridge`, `shell.openExternal`, Tauri commands;
  - `app signing and platform config`: `codeSigningCertificate`, `signingConfigs`, `usesCleartextTraffic`, `NSAllowsArbitraryLoads`, `allowBackup`, `autoUpdater`, plus the files `tauri.conf.json`, `electron-builder.*` and `forge.config.*`;
  - `cryptography`: `createCipheriv`, `crypto.subtle`, `CryptoJS`, MD5/SHA-1 hashes.
- **Wider existing categories:**
  - `secrets`: `*.jks` and `*.keystore` files;
  - `auth and sessions`: `reauthenticate*`, `updatePassword`, `updateEmail`;
  - `file uploads`: archive libraries (`adm-zip`, `unzipper`, `yauzl`, `JSZip`) and EXIF;
  - `headers and CORS`: `X-Forwarded-For`, `X-Real-IP`.
- A plain version bump in `app.json` still prints nothing (tested).

## Tests

- `hooks/risk.test.mjs`: the new categories, the IDs in the message and the `app.json` negative case.
- `hooks/stack.test.mjs`: Electron, Tauri and Capacitor detection.
- `test/structure.test.mjs`: every `PostToolUse` category has controls, and every control it names exists in `SKILL.md`. If a control is renumbered, the test fails instead of the hook pointing to a control that doesn't exist.
