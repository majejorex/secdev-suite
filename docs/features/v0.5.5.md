# v0.5.5: a sign-off says it did not hunt (2026-11-04)

## Problem

A PASS was easy to read as a pentest. The checklist told the model to load `security-audit` for a deeper look, and that name is Cloudflare's audit skill, a different product. A route that checks the owner could be marked MET while a second route for the same resource skipped the check, and no eval covered that. A lifecycle script that downloads or runs code was outside P0-16.

## Changes

- `security-checklist`: sign-off writes `Hunt: not done` and design mode omits it, same as `Verdict:`. Escalate says not to load `security-audit`, and points a bug hunt at the `claude-security` plugin. P0-16 is NOT MET when a `preinstall`, `postinstall` or `install` script downloads or runs code. The file stays at 14,999 characters (budget 15,000). No new control, skill, reference or hook.
- READMEs name the two other products and link to them.
- Evals: critical case `second-route` (an owner check on `/orders/:id`, none on `/orders/:id/invoice`).

## Evidence

`npm test` passes (74 tests). Full eval run, 30 cases × 3, [docs/evals/v0.5.5.md](../evals/v0.5.5.md): model `claude-sonnet-5-5`, cost $17.67, gate FAIL. `second-route` is 3/3. `rules-change` and `es-authz-callable` are 2/3: one answer each loaded the skill and described the issue without the `Verdict:` line. A re-run of those two cases passed 3/3 (cost $1.20). No tag until that full-run gate is accepted or the run is repeated.
