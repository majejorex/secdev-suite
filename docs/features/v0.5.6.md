# v0.5.6: fewer false reminders from the edit hook (2026-11-17)

## Problem

The `post-edit` hook reminded the agent to load `security-checklist` after edits that said nothing about risk: a `password="x"` or `stripe` in a test fixture, or `role="button"` in markup. One real month of sessions (3,942 transcripts) showed 912 sessions with a reminder.

## Changes

- `hooks/risk.mjs`: content rules are skipped for test files (`*.test.*`, `*.spec.*`, `tests/`, `__tests__/`, `e2e/`). Path rules still apply, so `tests/firestore.rules`, `.env` or a Dockerfile under a tests folder still warn.
- `hooks/risk.mjs`: a fully quoted ARIA value (`role="button"`, `role: 'dialog'`) is not an authorization role. Values that only start with an ARIA word (`group-admin`, `log-reader`) still warn.
- No skill, description, control or eval changes.

## Evidence

`npm test` passes (76 tests). Replaying the same 30 days through the old and the new classifier: 912 to 759 sessions with a reminder (-16.8%). Reminders for `req.auth`, `onCall(`, `stripe` and `allow create` are unchanged. An independent review found one bug in the first draft (ARIA prefix match silencing `group-admin`); fixed with tests before merge (#27).

Known trade-offs: server code under an `e2e/` or `tests/` folder no longer warns by content, and an ARIA value on the same line as a real role does not hide it (the other match still warns).
