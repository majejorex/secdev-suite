# v0.4.1: answers name the key risk, and the evals check it (2026-11-03)

## Why

In the v0.4.0 eval run all 14 cases passed. In four of them the answer was missing an expected key word, but that didn't count:

| Case | Expected | What the answer said |
|---|---|---|
| `rules-change` / `es-rules-change` | "mass assignment" | It proposed `affectedKeys().hasOnly([...])`, the fix, without naming the risk |
| `stripe-webhook` | `constructEvent` | "checks the Stripe signature against the raw body" |
| `ci-deploy-workflow` | `permissions` | "a read-only token" and an explicit refusal of `pull_request_target` |

The concept was always there. Only the exact word was missing, and the evals didn't enforce it.

## Changes

- **Skill (P0-03).** The control now names the risk: writes limited to the allowed fields (`keys().hasOnly` in rules, a field allowlist in the API), so nobody can set their own `role`, `isVerified` or `balance` (**mass assignment**). Before, this only lived in `references/firebase.md` and in API3.
- **Synonyms in evals.** A `mustMention` item can now be a list of alternatives, and any of them counts. For example, `["constructEvent", "raw body"]` or `["permissions", "read-only token", "contents: read"]`. A Spanish answer that keeps the English term ("mass assignment") also passes.
- **Mentions count.** A missing mention now fails the case. Before, it was only printed.
- **Test.** `test/structure.test.mjs` checks that every `mustMention` item is a word or a non-empty list of words.
